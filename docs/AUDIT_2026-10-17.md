## 2. Security and correctness findings

Each finding states severity, confidence, effort (S/M/L), evidence, and fix. Confirmed means the described behavior was reproduced or established by source/search; it does not imply that it occurred in the owner's account.

### BUG-1 — Missing account collections are interpreted as verified empty collections

**High · Confirmed · M.** Locations: `src/agent_trading/account.py:96`, `:102`, `:115`, `:135`; `src/agent_trading/order_gate.py:182`.

`parse_snapshot` uses `raw.get("positions") or []` and `raw.get("orders") or []`. It cannot distinguish “the read succeeded and there are no orders” from “the order read was omitted/failed.” An open buy can therefore be absent from the snapshot used by the final gate. A synthetic snapshot with valid identity, fresh timestamp, $1,000 cash/value and settled funds, but **neither collection present**, parsed successfully and approved one ordinary $90.45 SPY buy ticket; blockers were empty. Cash reconciliation cannot detect an omitted open order when it has not filled.

**Fix:** require explicit list-valued positions and orders, validate order state/side and collection completeness, and retain a fail-closed completeness marker when saving/loading snapshots. Reject incomplete old records until reimported from successful reads. Also validate the saved-snapshot boundary (`account.py:157`), which currently constructs the dataclass directly. Preserve identity, age, reconciliation, and settled-cash checks. This is a new completeness gap, not a re-report of the closed “no reconciliation” finding.

### BUG-2 — NaN cash-reserve configuration bypasses the minimum-reserve check

**High · Confirmed · S.** Locations: `src/agent_trading/config.py:441`, `:458`; `src/agent_trading/order_gate.py:82`.

The upper-bound account limits use a rejecting chained comparison, but `min_cash_reserve` uses only `value < HARD_LIMITS[...]`. For NaN that expression is false. `buy_headroom` then feeds a NaN reserve expression into `min`, where the other finite caps can win. Synthetic evidence: a $900 account with $750 invested and $150 cash rejected a $30.15 ticket under the normal $200 reserve, but approved it with `min_cash_reserve=float('nan')`; `validate` accepted that configuration. No repository configuration was edited.

**Fix:** reject booleans, non-numbers, NaN and infinities before all numeric limit comparisons, including the lower-bound reserve, capital, and costs. Keep every existing limit and inequality unchanged or stricter. Add adversarial config tests. Do not change `HARD_LIMITS` values.

### BUG-3 — Holdout use is opt-out, and selection still simulates the full history

**High · Confirmed · M.** Locations: `src/agent_trading/cli.py:111`; `src/agent_trading/cli_research.py:387`; `src/agent_trading/research/tournament.py:245`, `:255`, `:465`.

`tournament` defaults `no_test=False`; `run(..., run_test=True)` calls `run_test` **before** reading `prior_test_evaluations`. Prior consumption is reported, not enforced. A completely mocked probe with an existing GTAA evaluation still dispatched GTAA plus four benchmarks to `run_test`; no real test data or registry was touched. Moreover, `run_selection` calls `_sim`, which builds weights and simulates `self.mkt` over its complete index, then slices metrics to selection dates. Thus `--no-test` prevents final test reporting but does not isolate the held-out rows from candidate execution.

**Fix:** make selection-only the safe default and physically restrict its market frames to `SELECTION`'s end before candidate execution. Check the immutable registry before any explicitly authorized, genuinely new evaluation; refuse previously consumed strategy/data identities and malformed registry lines. Keep `ACCEPTANCE`, splits, and historical records untouched. Add tests that a future-row sentinel is never passed to selection and that repeated test dispatch is rejected. No claim of an already biased winning strategy is made: existing causal candidate tests pass, and selection metrics are currently sliced.

### DATA-1 — A lagging history feed is completed with invented OHLCV values

**High · Confirmed · M.** Locations: `src/agent_trading/dashboard/pipeline_collect.py:62`; `src/agent_trading/dashboard/pipeline_score.py:19`, `:97`.

When history stops before the as-of session, `latest_bars` inserts a row with open=quote close, high/low derived from two closes, and volume=the prior 20 bars' median. The row then passes `validate_bars` and participates in `dollar_volume`, which controls liquidity eligibility and share-class selection. The flag only explains the closing-price substitution. A synthetic 80-bar history plus a current quote produced an accepted 81st OHLCV row, including inferred volume.

**Fix:** keep a verified closing quote as a separate, explicitly sourced close-only observation. Require actual OHLCV wherever OHLCV or liquidity is needed; missing volume must remain unavailable and must not pass the gate. Review the related range-repair path in `providers.py:342` without silently converting repairs to measurements. This conflicts with `CLAUDE.md`'s no-fabrication rule; availability is not a justification to relax it. Correct future collection behavior; never rewrite immutable historical snapshots. If a methodology decision is required, pre-register it separately with a new version and changelog, outside the unchanged-spec refactor.

### SEC-1 — CSV exports allow spreadsheet formulas

**Medium · Confirmed · S.** Locations: `src/agent_trading/dashboard/fmt.py:106`; `src/agent_trading/dashboard/site_downloads.py:37`, `:70`, `:161`, `:222`, `:253`, `:264`.

`csv_value` returns strings unchanged. Watchlist exports preserved test names beginning with each of `=`, `+`, `-`, `@`, tab and carriage return. Leaders has its own four-prefix defense but preserved a tab-prefixed formula. CSV quoting protects delimiters, not spreadsheet execution. Company names, issuer excerpts, reasons, and owner notes can reach these cells.

**Fix:** neutralize dangerous **text** prefixes in the shared `csv_value`; use it in every exporter and remove the narrower duplicate defense. Preserve genuine numeric negatives as numbers. Test all six prefixes, quoted cells, multiline text, and ordinary negative numeric values. This intentionally changes unsafe CSV cells, not scoring.

### SEC-2 — Imported symbol strings can escape the price-cache directory

**Medium · Confirmed · S.** Locations: `src/agent_trading/data/cache.py:12`; `src/agent_trading/data/robinhood.py:26`; `src/agent_trading/data/service.py:145`, `:158`; `src/agent_trading/cli_data.py:28`.

`cache_path` returns `cache_dir / f"{symbol.upper()}.csv"` without validating a ticker or checking containment. A pure path probe with `../escaped` resolves outside the cache. The MCP JSON importer trusts the payload's symbol and passes it into cache read/write operations. This is a local import trust-boundary issue, not a remotely exposed server exploit; no escaping file was written during the audit.

**Fix:** validate imported symbols against the supported ticker grammar and reject separators, drive prefixes and absolute paths; independently require the resolved destination to remain inside the configured cache. Apply the same policy to other symbol-derived storage paths. Explicit user-chosen *input* file paths are a legitimate CLI feature and should remain usable.

### SEC-3 — Public audit persistence bypasses secret redaction

**Medium · Confirmed persistence gap; actual disclosure Suspected · S.** Locations: `src/agent_trading/dashboard/__main__.py:92`, `:107`, `:279`; `src/agent_trading/dashboard/store.py:77`; `.github/workflows/research-dashboard.yml:126`.

Unexpected exception text is copied into `Store.audit`, whose JSON writer does not call `redact`. The dashboard entry point uses `logging.basicConfig`, rather than the handlers with `RedactingFilter`. An in-memory `mock_open` probe showed that a registered synthetic redaction marker remained in an audit write even though `redact(marker)` removed it. The data-branch commit occurs before site-build secret scanning, so that later scan cannot protect an already committed audit line. Normal HTTP/provider errors are often sanitized; no real leaked secret was found.

**Fix:** persist safe error codes/type names, or recursively redact free-text event values before append; install the existing redaction filter on dashboard logging handlers as well. Test raw exceptions at both boundaries using synthetic markers. Do not remove audit events, rewrite the existing log, or dump payloads for diagnostics.

### BUG-4 — Final sell validation accepts invalid quantities

**Medium · Confirmed · S.** Locations: `src/agent_trading/order_gate.py:188`; `src/agent_trading/risk.py:281`; `src/agent_trading/live.py:41`.

The buy validator checks finite positive quantity, but the sell loop checks only held quantity, duplicates and limit price. Synthetic sell quantities -1, 0 and NaN all entered `GateResult.approved`. `risk.check_order` also accepts NaN quantities because its inequality checks do not reject non-finite values. The normal live builder obtains positive quantities from parsed holdings, and SQLite's positive/NOT NULL constraints block these malformed quantities at persistence: this probe establishes a defense-in-depth gap, **not evidence of an emitted invalid live ticket**.

**Fix:** validate side, finite positive quantity and finite positive price uniformly before buy/sell branching, and validate state values in the public paper-order check. Keep SQLite constraints and independent gate checks. Test malformed sell tickets, not just oversized sells.

### DATA-2 — Price validation accepts infinite values

**Medium · Confirmed · S.** Location: `src/agent_trading/data/validation.py:110`.

The validator rejects NaN with `isna`, but does not reject infinity. A one-row synthetic bar with finite open/close/low, infinite high and infinite volume passed all checks. That data can corrupt ATR or liquidity calculations; final live close checks alone do not validate all inputs.

**Fix:** require all required numeric values to be finite before range, split, frozen-feed and staleness checks. Add +/-infinity cases for every OHLCV field. Preserve all existing rejection rules and error provenance.

### DATE-1 — Some remaining date calculations use weekdays or the host timezone

**Low · Confirmed · S.** Locations: `src/agent_trading/live.py:272`; `src/agent_trading/cli.py:40`; `src/agent_trading/data/validation.py:143`.

The NYSE calendar exists and the gate uses it, but reconstructed live entry dates still use `np.busday_offset`; CLI defaults use host `date.today`; generic bar age uses weekday counts. These are different semantics from exchange sessions/New York dates. They can mislabel an inferred entry date or make a host in another timezone choose a different as-of day. They do not undo the final exact-date ticket check.

**Fix:** label inferred dates as inferred, use the exchange calendar for session dates, and select a New York date at the application boundary. Keep conservative staleness rejection; changing an existing age budget to accept more data is outside a behavior-preserving refactor and must not silently weaken it.

## Appendix C — Reproducing the frozen fixture baseline

Run with the audited Python dependencies, `PYTHONPATH` pointing at this checkout's `src`, and bytecode disabled. Supply a **new** temporary directory as the script's argument. This harness patches clocks only in memory; it does not modify source, production snapshots, or the research registry. SHA-256 manifests cover both fixture data and rendered site outputs. The initial ordinary CLI build and verification commands are recorded in Phase 0.

```python
from contextlib import ExitStack
from datetime import UTC, date, datetime
import hashlib
import importlib
import json
from pathlib import Path
import sys
from unittest.mock import patch
from tests.dashboard_fixtures import demo_site

root = Path(sys.argv[1]).resolve()
modules = [
    "store",
    "site_build",
    "site_layout",
    "site_goal",
    "site",
    "earnings_verdicts",
    "pipeline_assemble",
    "pipeline_context",
    "pipeline_details",
    "providers",
    "refresh",
    "tradability",
]


class FrozenDateTime(datetime):
    @classmethod
    def now(cls, tz=None):
        value = cls(2026, 10, 17, 20, 0, 0, tzinfo=UTC)
        return value.astimezone(tz) if tz else value.replace(tzinfo=None)


class FrozenDate(date):
    @classmethod
    def today(cls):
        return cls(2026, 10, 17)


for name in ("frozen-a", "frozen-b"):
    if (root / name).exists():
        raise RuntimeError("Use a new temporary output directory")

with ExitStack() as stack:
    for name in modules:
        module = importlib.import_module("agent_trading.dashboard." + name)
        if getattr(module, "datetime", None) is datetime:
            stack.enter_context(patch.object(module, "datetime", FrozenDateTime))
        if getattr(module, "date", None) is date:
            stack.enter_context(patch.object(module, "date", FrozenDate))
    for name in ("frozen-a", "frozen-b"):
        demo_site(root / name)


def hashes(base):
    return {
        path.relative_to(base).as_posix(): hashlib.sha256(path.read_bytes()).hexdigest()
        for path in sorted(base.rglob("*"))
        if path.is_file()
    }


first, second = hashes(root / "frozen-a"), hashes(root / "frozen-b")
assert first == second
(root / "frozen-sha256.json").write_text(json.dumps(first, indent=2), encoding="utf-8")
print(len(first), "files match")
```
