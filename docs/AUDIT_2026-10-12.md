## 2. Architecture (as found)

```
Scheduled Claude session --(MCP, read-only)--> JSON in scratchpad --> `agent_trading` imports
   --> strategies A (scanner, paper only), B (desk), C (GTAA)
   --> RiskEngine (risk.py) --> PaperBroker (paper.py, SQLite)      [simulation]
                            --> live.py: manual ORDER TICKETS      [owner places by hand]
   --> daily report (reports/) + run manifest (data/runs/)
```

- **Config** (`config/settings.yaml`, `config.py`): the loader refuses `mode` other than `paper`, and refuses short, margin, options or crypto flags. Live tickets are a separate `live:` section (`enabled: true`, `capital: 1000`, strategies B and C).
- **Risk** (`risk.py`): per-trade planned risk of 0.5% (TQQQ/SQQQ 0.25%), 1.5% aggregate, 1% correlated, 25% max position, cash-only, a 1% daily loss stop, and an 8% drawdown shutdown.
- **Live tickets** (`live.py`):
  - require a verified snapshot of ••8204 that is under 24 h old;
  - size on at most $1,000 through the same RiskEngine;
  - block buys while any buy order is open;
  - reconcile the previous tickets.
- **Scheduler:** five Claude desktop scheduled tasks (premarket 08:30, intraday 12:30, postclose 16:30, weekly Friday 17:30, and a one-time alert test). Only one run so far: intraday at 2026-10-12 14:36 UTC, status "succeeded".

## 4. Order-placement paths

- **Python code:** none. No broker client, no order API, and no network access other than Alpha Vantage market data. This is enforced by `tests/test_safety_guards.py`.
- **AI sessions:** the MCP exposes order tools. The prohibition against using them is enforced by:
  - the CLAUDE.md rules and scheduled-task prompts (soft controls);
  - Robinhood trade approvals (broker-side, a hard control that the owner can switch off).
- **The owner:** places tickets by hand. Nothing in code can force the owner's manual order to respect the limits, so the limits must be applied **before** a ticket is written.

## 5. Unattended operation

**Not genuinely unattended.**

- Runs are Claude desktop scheduled tasks. They fire only while the laptop is on and the Claude app is running, and a missed run is executed when the app next opens.
- The Python code cannot fetch broker data itself. It depends on an AI session to call MCP tools and save the JSON.
- There is no process supervisor, no heartbeat or dead-man alert for missed runs, and no alert channel other than the session's own PushNotification.
- Holidays are not modelled.

## 6. Defects and risk gaps found

| # | Severity | Finding |
|---|---|---|
| G1 | High | **No persistent kill switch.** Nothing blocks tickets across restarts except editing the config |
| G2 | High | The **master-prompt account limits do not exist in code:** $100 max order, $800 max exposure, $200 cash reserve, $200/day purchases, 3 entries/day. The current caps are $250 per position and the risk budget only |
| G3 | High | **Leveraged and inverse ETFs (TQQQ, SQQQ) can get live tickets** through Strategy B. The master prompt prohibits them for the account |
| G4 | Medium | **Unsettled cash is not considered.** The snapshot has no `unsettled_funds`, and sizing uses `cash`. The account is `limited_margin` at the broker |
| G5 | Medium | **No final deterministic gate between sizing and the ticket file.** A sizing bug would flow straight into a ticket |
| G6 | Medium | **Tickets can be built from data that is up to 4 business days old** (the general staleness limit), and from a snapshot that is up to 24 h old. Nothing checks that the snapshot is from the ticket day, or that the bar is the session's close |
| G7 | Medium | **Account reconciliation only checks identity and age.** It does not check that cash + positions × price ≈ total value |
| G8 | Medium | **Exchange holidays are not modelled.** `gtaa.is_rebalance_day` uses weekdays, so it **misses a month-end rebalance when the month's last weekday is a holiday** (e.g. Memorial Day, Mon 2027-05-31). `next_session` also ignores holidays |
| G9 | Low | Drawdown shutdown is 8%; the master prompt asks for a 5% risk review |
| G10 | Low | The scheduled tasks depend on the laptop and the app; there is no missed-run alert |
